# sigbot: сигнальный бот по топ 30 USDT перпетуалам

Один процесс на домашнем сервере: собирает данные Binance, Coinbase и индекс страха и жадности, раз в час ищет сигналы, ведёт сделки по заранее заданным правилам, публикует посты в Telegram канал на английском, показывает веб панель. Ордеров бот не выставляет никогда, ключи бирж ему не нужны.

## Установка

Нужен Python 3.11 или новее.

    git clone https://github.com/RifatAF/sigbot1 && cd sigbot1
    python3 -m venv .venv && . .venv/bin/activate
    pip install -r requirements.txt
    playwright install chromium          # для картинок сигналов

Создай `.env` рядом с `config.yaml` (в git он не попадает):

    TELEGRAM_BOT_TOKEN=...
    TELEGRAM_CHANNEL_ID=-1003595508596
    TELEGRAM_OWNER_ID=569798955
    GEMINI_API_KEY=...
    DASHBOARD_TOKEN=придумай_длинную_строку   # необязательно, закрывает панель паролем

## Запуск

    python -m sigbot backfill       # история за период бэктеста (около 40 минут на 30 монет)
    python -m sigbot backtest       # отчёт в reports/
    python -m sigbot run            # бот

Чтобы бот работал постоянно и поднимался после перезагрузки, `deploy/sigbot.service` (systemd):

    sudo cp deploy/sigbot.service /etc/systemd/system/
    sudo systemctl enable --now sigbot
    journalctl -u sigbot -f          # живой лог

## Команды владельца

Напиши боту `/menu` в личке. Отвечает только владельцу (`TELEGRAM_OWNER_ID`).

| Кнопка | Что делает |
|---|---|
| Status | открытые сделки, последний скан, посты в ожидании |
| Health | состояние сборщика по компонентам, пропуски за сутки |
| Mode | paper, confirm, auto |
| Pause / Resume | остановить и возобновить публикации (скан продолжается) |
| Kill switch | остановить скан и все публикации |
| Risk | диапазон риска на сделку и лимит сигналов в день |
| Leverage | потолок плеча для канала и личный |
| Coins | список монет; `/coins BTC,ETH,SOL` задаёт свой, `/coins auto` возвращает топ 30 |
| Schedule | час ежедневной заметки (UTC) |
| Export CSV | журнал сигналов и исходов файлами |
| Post mortem | разбор убыточных сделок за неделю |
| Bloggers | точность авторов |
| Post method | опубликовать и закрепить пост с описанием метода |

**Блогеры.** Перешли боту пост или скриншот. Gemini извлечёт монету, ожидание, уровни, условия и источник, бот покажет результат, ты подтверждаешь кнопкой. Подтверждённые уровни сливаются в зоны внимания и через 14 дней истекают. На вход в сделку они не влияют: только строка в посте и линии на картинке. Чужие тексты и картинки в канал не попадают.

## Режимы публикации

| Режим | Поведение |
|---|---|
| `paper` (по умолчанию) | посты сразу идут в канал с пометкой `#forwardtest`, в журнале `mode=paper` |
| `confirm` | каждый пост сначала приходит тебе с кнопками Publish и Drop |
| `auto` | посты идут в канал без пометки и без подтверждения |

Режим меняется в `config.yaml` (`publishing.mode`) или кнопкой Mode. Значение из админки главнее конфига.

Перед любой отправкой текст проверяется: каждое число в посте должно совпадать с числом движка. Если нет, пост не уходит, запись `blocked` в таблице `posts`, тебе приходит сообщение. Gemini пишет только комментарий без цифр; если он вставил цифру, комментарий выбрасывается.

## Health

    python -m sigbot health

Показывает компоненты (свечи, OI, фандинг, ликвидации, премиум, страх и жадность), покрытие минутных свечей за 72 часа и число пропусков. Тот же отчёт: кнопка Health в боте и `http://127.0.0.1:8787/api/health`.

Как устроен сборщик: свечи, OI и фандинг берутся по REST, каждый цикл догружает всё с последней сохранённой метки. Поэтому обрыв сети и перезапуск сами закрывают пропуски, а первичные ключи исключают дубли. Ликвидации идут через WebSocket с переподключением; каждый обрыв пишется в таблицу `gaps`.

## Экспорт журнала

    python -m sigbot export --out export     # export/signals.csv, export/outcomes.csv

Журнал `signals` и `outcomes` только на добавление: UPDATE и DELETE запрещены триггерами SQLite. Каждый сигнал хранит версию параметров и снимок признаков.

## Как читать отчёт бэктеста

`reports/backtest_<версия>_<время>.md` (и `.json` для панели):

* **Период вне выборки.** Первые 90 дней только для настройки, считаются лишь окна после них.
* **Walk forward.** Окно 90 дней выбирает порог силы сигнала из сетки, следующие 30 дней торгуются с ним. Таблица окон показывает выбор и результат каждого месяца.
* **Стратегия против buy and hold и кэша.** Доходность стратегии после комиссий (0.05% за сторону) и фандинга сравнивается с покупкой всех монет равными долями, с BTC и с нулём (кэш).
* **Вердикт.** «Обгоняет», только если стратегия выше и buy and hold, и кэша.
* **R.** Результат в единицах риска: −1R значит потерян запланированный риск, +2.5R значит прибыль в 2.5 раза больше риска.
* **Выходы.** Сколько сделок закрылось по стопу, безубытку, целям, отмене идеи, времени.

Параметры привязаны к `params_version` в `config.yaml`. Изменил любой параметр: подними версию (v2), иначе бот откажется записать отчёт с другими параметрами под старой версией.

## Панель

`http://127.0.0.1:8787` (с `?token=...`, если задан `DASHBOARD_TOKEN`). График, маркеры входа и выхода с результатом в R, переключатель Live/Backtest. В канал идут только живые сигналы. PNG любого сигнала: `/chart/<id>.png`.

Доступ снаружи через Cloudflare Tunnel, в конфиг `cloudflared` добавь:

    ingress:
      - hostname: sigbot.твой-домен
        service: http://127.0.0.1:8787

## Правила v1

* **Вход.** Дивергенции (регулярные и скрытые, бычьи и медвежьи) цены против RSI, CVD фьючерсов, CVD спота и открытого интереса. Нужна одна регулярная или две скрытые, композитный индекс не против, сделка по тренду 4ч.
* **Индекс.** z-оценки изменения OI против цены, фандинга (отрицательный за лонг), CVD спота, поглощения на фьючерсах, премиума Coinbase и ликвидаций. Отсутствующие данные пропускаются, вес перераспределяется.
* **Фильтр страха и жадности.** Выше 85 лонги запрещены, ниже 15 запрещены шорты.
* **Уровни.** Стоп за экстремумом дивергенции плюс 0.3 ATR (не ближе 0.7 ATR). TP1 = 1.2R, закрывает 50%. TP2 = 2.5R, либо ближайший кластер ликвидаций в диапазоне от 1.8R до 4R.
* **Ведение.** На половине пути к TP2 стоп переносится в безубыток. Закрытие часовой свечи за уровнем отмены идеи закрывает сделку. Через 72 часа сделка закрывается по времени. Усреднения нет, второго входа в v1 нет.
* **Риск.** От 0.5% до 1.5% депозита по силе сигнала. Позиция = риск / расстояние до стопа. Плечо = позиция / депозит, потолок x25. Далёкий стоп уменьшает плечо, сигнал остаётся.
* **Отбор.** Не больше 2 сигналов в день. Сделки в одну сторону по монетам с корреляцией выше 0.8 считаются одной ставкой.

## Допущения

* **Ликвидации.** Источник только Binance: Bybit на старте не нужен. Поток `forceOrder` отдаёт не все ликвидации, а одну на символ в секунду, поэтому объёмы в нём занижены. Истории ликвидаций в открытом доступе нет: в индекс они входят только за период, который бот записал сам.
* **Карта ликвидаций.** Оценивается по приросту открытого интереса при плечах 10, 25, 50 и 100.
* **Премиум Coinbase.** Считается по BTC и используется как общий фон рынка для всех монет.
* **Фандинг.** В живой работе пишется текущий прогнозный фандинг раз в 5 минут, в бэктесте используется фактический.
* **Блокировка публикации.** По решению владельца paper режим публикацию в канал не блокирует. Публикацию останавливают только пауза и kill switch.
* **Gemini.** Основная модель `gemini-flash-latest`, при сбое `gemini-flash-lite-latest`. Если обе недоступны, пост уходит без комментария.
